# 工程基本原则

本文件定义在本仓库工作的所有 Coding Agent 必须遵守的通用工程原则。

## 核心原则

1. **简单优先，避免过度设计**：优先采用直接、可读、可维护的实现；不为尚不存在的需求提前引入通用抽象层、框架或复杂目录。
2. **优先复用现有能力**：新增功能前先检查项目已安装的依赖、UI 基础组件、认证与数据库封装，避免引入功能重复的包。
3. **保持改动范围最小**：每次任务聚焦单一清晰目标，改动保持局部且易于代码审查。
4. **需求与实现可追溯**：业务开发必须对应明确的 `docs/` 产品规格（Intent / PRD / SPEC / 指标合同）、GitHub Issue 或用户任务书，不凭空臆造需求。
5. **不做无关重构**：保护现有文件与未提交改动，不顺手修改与当前任务无关的代码或样式。
6. **不引入未经验证的假设**：
   - 不假设未检查的目录结构、配置或运行环境；一切事实以仓库实际文件为准。
   - **严禁伪造业务数据或运行结果**：不制造虚假监测记录、趋势、客户评价、排名或提升比例；明确区分“未知”“未提及”“暂无数据”和“未开放”。
7. **优先保持接口与行为兼容**：调整已有 API、数据结构或公共契约时，评估已有消费者与版本语义，避免静默破坏。
8. **记录重要决策与取舍**：涉及架构边界、数据模型、依赖引入或安全权衡的决策，应在交付说明或对应任务记录中说明原因与影响。
9. **保护权威产品文档**：不修改或删除已有产品文档来迁就代码实现；发现文档冲突或技术阻塞时先说明并记录，不自行挑选最省事的解释。

## 规则冲突处理

当不同来源的指令或规范发生冲突时，按以下优先级处理：

1. **系统与开发者强制指令及安全操作约束**：禁止泄露密钥、禁止破坏性操作、禁止伪造验证结果。
2. **用户明确指令与已确认授权**：如当前任务范围、补充工程要求、保留/不修改要求。
3. **仓库入口与产品权威合同**：根目录 [AGENTS.md](../../AGENTS.md)、本治理体系，以及 [产品文档入口](../../docs/README.md) 指向的 Intent / PRD / SPEC / 指标合同。
4. **仓库实际实现与运行证据**：用于判断现状、可执行步骤和验证边界，不把存量实现提升为不可变要求，也不把已确认目标写成已经实现。
5. **历史资料与未启用流程**：如 `docs/archive/`、`openspec/` 或已停用的旧架构入口，仅作参考，不自动成为现行规范。

涉及安全性、数据完整性和验证真实性的要求，不得因追求进度或简化步骤而被绕过。若权威文档间存在实质矛盾，应先记录具体冲突并向用户说明。
