# B07 到期清除及最小凭证

[Issue #7](https://github.com/Godyu97/geo-pro/issues/7) · [T-M0-01](M0.md#t-m0-01) · [B06 删除与恢复](B06-brand-deletion.md) · [数据库部署说明](../architecture/database-deployment.md)

## 清除范围

| 对象 | 到期后的处理 |
| --- | --- |
| 品牌版本、正文和品牌草稿 | 按品牌键及负责人删除。品牌相关的请求记录清除内容指纹，保留不透明标识和幂等结果以防旧提交重建品牌。无法归属的旧草稿请求键按负责人失效。 |
| 本人导出 | B05 在下载时重建文件。清除冻结前可能含目标资料的导出记录及其指纹，保留其他账号的记录和仅含账户资料的记录。已下载的系统外文件由持有人管理。 |
| 额度和费用 | 保持冻结直到最后一笔已受理费用核对。待核对时继续用既有 B10 账本按归属查询和对账。随后以集合写入保留尝试与预约标识、类别、金额最小单位、币种及两次时间，再级联清除品牌及额度链。 |
| 清除凭证 | 保留品牌和负责人的不透明关联、冻结与清除时间、完成阶段与失败代码。仅受控服务端可读取清除凭证及费用页。 |
| 附件、回答证据、报告、业务缓存和其他在线副本 | 当前业务数据层尚未接入这些存储。各消费者应应用下文接入合同。 |

品牌的期限继续沿用 B06。清除按截止时间与品牌标识分页，每页最多 25 个品牌，每个品牌单独使用事务及阶段保存点。PostgreSQL 先锁负责人，再锁品牌。SQLite3 使用即时事务。正文、导出与费用阶段均通过集合语句读写。阶段提交后，重试从剩余项开始。

## 受控执行

在具有已授权操作系统及目标数据库访问权的服务端运行。检查目标环境后用以下命令处理到期数据或追踪结果。

```sh
pnpm --silent brands:purge run 25
pnpm --silent brands:purge run 25 <next.at> <next.id>
pnpm --silent brands:purge inspect <owner-id> <brand-id>
pnpm --silent brands:purge inspect <owner-id> <brand-id> <next.kind> <next.reservationId> <next.attemptId>
pnpm --silent brands:purge retry <owner-id> <brand-id>
```

`run` 返回本页结果及游标。继续处理后续页面，并按品牌重试失败页中的剩余项。遇到事务结果未知时，先用 `inspect` 查持久化进度。遇到 `unresolved-costs` 时，先通过既有费用核对流程处理已受理尝试，再重试该品牌。应用的普通账号、维护 Web 页面和下载 API 均无法调用这些命令。

## 恢复顺序

1. 在主库仍可核对时，暂停清除写入，使用 `pnpm --silent brands:purge manifest` 生成清单页。效果以已持久化的清除记录为准，包含已经开始、部分成功或完成的品牌。使用返回的 `next` 运行 `pnpm --silent brands:purge manifest <next>`，直到游标为空。将 JSON 原样写到权限受限的独立恢复介质，记录来源、页数、完整性摘要和交接时间。每轮清除后刷新。恢复作业所用的备份与清单需独立保存。
2. 将备份恢复到与用户流量隔离的目标，迁移到当前 Schema 并核验目标与清单来源。核对独立介质的清单齐全、完整，并覆盖到最新的清除记录。恢复点早于清单记录时，重放也会冻结被恢复成活跃状态的品牌。
3. 使用恢复库的服务端配置执行 `pnpm --silent brands:purge replay <page.json>`，每页检查退出码和结果。缺页、清除失败或无法核对最新清单时保持隔离。仅剩待核对费用时，确认正文及导出已清除，按独立账务资料核对后再重试。清单只承载删除决定，账务恢复使用独立账务资料。
4. 用授权测试身份确认目标品牌已不可读、旧下载不可用，再启用用户流量。清除后 30 天内退役备份是 D4 的工程目标。实际备份权限、独立保存、轮换、保留依据和披露由 [Issue #21](https://github.com/Godyu97/geo-pro/issues/21) 核验。

## 后续存储接入合同

- 证据和附件存储须能按负责人和品牌定位所有版本、下载、衍生对象及副本。接入时先将冻结权限检查应用到写入和旧下载链接，再添加实际清除步骤，记录独立进度和失败。外部对象删除应幂等并可核对，使重试仅涉及剩余对象。缓存和副本需验证失效、故障恢复以及恢复旧副本时仍拒绝访问。
- 报告读取先鉴权，从授权快照取得不可变的品牌关联，再调用服务端的 `readAuthorizedReportEvidence`。当其返回 `no-longer-reviewable` 时，在授权的界面上用相应语言提示证据已清除。保留原报告字节及可独立复算的快照口径。报告页面联调由 [Issue #30](https://github.com/Godyu97/geo-pro/issues/30) 承接。
- 领域接入前用隔离 fixture 回归到期前后、失败重试、并发写入、旧副本重放和越权访问。报告须比对源证据清除前后同一快照的字节或哈希。
