# 二期开发计划：让用户从建品牌走到复测报告

2026-11-26 项目负责人评审决定。M0/M1/M2 继续标识产品能力与历史交付范围。二期的出单顺序取决于用户现在在哪一步走不下去。

**首要结果**是普通用户从首页进入自己的工作台，创建品牌、确认题集、发起真实监测、打开原回答，从证据创建任务，完成内容审核交付，再核验公开页面并复测。管理员可以按用户和 group 找到任一品牌、维护品牌资料和成员、查看用户的监测、内容及报告。账号模型见 [PRD](../02-产品需求文档-PRD.md)。

## 开工顺序和取舍

1. [账号与 group](https://github.com/Godyu97/geo-pro/issues/188)、[自助品牌入口](https://github.com/Godyu97/geo-pro/issues/189) 和[整体验收](https://github.com/Godyu97/geo-pro/issues/190) 可立即开始。走查从已有开发品牌起步，自助入口就绪后补走首次使用路径。#188 交付后接[管理员工作台](https://github.com/Godyu97/geo-pro/issues/191)、#179 和 #182。
2. 素材交付 #177、资料转事实 #180、业务反馈 #181、报告分享 #183、消费者回答入证 #185 各自补通一个实际操作。下一个模块尚无可用路径时，优先补该模块。权限泄露、错误交付或重复扣费等直接损害用户的问题随相关路径修复。
3. 渠道变体审批 #178、外部发布连接 #184、媒体核对联动 #186、门店专属简报 #187 排在首版覆盖之后。仅当真实使用被其中一项阻断，或负责人明确选择扩展时，再将对应工单转为可开工。已知核对失败的媒体及未审变体不得用于正式交付，可先走已审核文本和人工发布路径。

## 开发环境就是业务验收环境

使用现有开发账号、数据库、Redis、私有 S3 和实际使用的通道，从正常用户入口操作并回读结果。每项只记入口、动作、实测结果与脱敏定位；有费用时记实际费用或待核对状态。现有自动化继续覆盖越权、故障、破坏性清除和双库兼容，邮件沿用长期 Mock。产品发布、外部付费和自然观察窗口各按实际条件处理。

在 #190 按上表登记已验证和仍卡住的模块。一个模块首版通过后推进下一模块，只有连接相邻模块的实际断点才新增 Issue。最终用同一品牌串起运行、证据、内容、公开核验和报告。效果和趋势遵守[指标与证据合同](../07-指标与证据合同.md)。
