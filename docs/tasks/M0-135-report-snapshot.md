# M0-135 报告快照

2026-11-24。 [Issue #135](https://github.com/Godyu97/geo-pro/issues/135) · [视觉验收清单](../08-验收场景与样例.md#ui-visual-checks) · [S-M0-12](../specs/M0.md#s-m0-12)

品牌负责人打开复测与报告后，应能先看到当前任务和下一步。已有仍有效的快照时，下一步是下载这份不可变 JSON。后继版本不改写旧文件，探索结论不声称因果。还没有快照时，不要下载，先打开观察计划。读取失败时保留标题，不显示快照编号和等级，并用键盘重新载入。

基线 `d8cbc3e3eea32d4d1bee7e5549a3b2dc4afe3ce3` 在隔离 Chrome 中文 375 像素复现。页面没有说明下一步。相关入口、复测和 D+7 待办排在快照之前，滚动到页首后「下载 JSON」的可见比例为 0。

- `/dashboard/reports` 留在工作台唯一的 `main#main-content` 内。标题是复测与报告。任务说明放在同一内容区。相关入口换行。
- 已有 `created` 快照时，主要动作是下载当前 JSON，只指向最新一份仍有效的快照。列表里仍可分别下载 JSON 和 HTML。后继快照写明上一份编号。
- 还没有快照，或列出的快照都已有后继版本时，主要动作是打开观察计划，不提供当前下载。
- 等级、意图和状态仍显示已保存的值。已知费用、待核对和工时仍按快照字节显示 N/A 和原因。
- 读取失败时标题仍是复测与报告，提示可重试，主要动作是重新载入当前地址。不显示快照编号、等级和品牌名称。其他账号打开同一品牌地址仍看不到这些内容。

## 隔离验收

Chrome 使用开发用回环 PostgreSQL、memory 缓存、回环 S3 和邮件 Mock。品牌和窗口都是合成数据。本轮没有请求供应商。比较没有传入发布核验，因此意图是 `diagnostic`，闭环为否。

| 场景 | 实际结果 |
| --- | --- |
| 当前快照 | `zh-CN` 与 `en` 在 375、768、1440 像素无横向溢出，且只有一个 `main`。中文可见「已有仍有效的报告快照。后继版本不会改写这份文件。探索结论不声称因果。下一步是下载当前 JSON。」主要动作「下载当前 JSON」只出现一次，指向该快照，375 像素在视口内。列表仍有一次「下载 JSON」和一次「下载 HTML」。状态是 `created`，没有 `superseded`。待办写明不会自动发起付费调用。已知费用是 N/A。中文 375 像素用 Enter 下载的 JSON 与接口字节一致，并包含「合成报告品牌」。切换英文后同一地址的 JSON 字节不变。 |
| 后继快照 | 纠正标签后，旧 JSON 字节不变，新 JSON 字节不同。同一两种语言和三种宽度无横向溢出。主要动作改为新快照。「created · 上一份」加旧编号留在内容区内。旧快照状态是 `superseded`。页面不显示品牌名称。 |
| 还没有快照 | 另一个合成品牌在 `zh-CN` 与 `en` 的 375、768、1440 像素无横向溢出。主要动作是打开观察计划，只出现一次，375 像素在视口内。没有当前下载，也没有上述快照编号。 |
| 读取失败 | 英文 375 像素保留标题 Retest & reports 和失败提示，看不到两份快照编号、`exploratory`、`diagnostic` 和品牌名称。重新载入在视口内。清除故障标记后用 Enter 回到原页，当前任务和新快照下载仍在。 |
| 其他账号 | 英文 375 像素仍是复测与报告标题，提示找不到该品牌或报告资源，看不到快照编号、品牌名称和当前下载。 |

八张 375 像素截图使用合成数据，保存在本地 `.cache/issue-135/report-snapshot/`，可由 `tests/e2e/report-snapshot.spec.ts` 重新生成。清理后回读，邮箱前缀 `report-snapshot-` 的账号、名称为「合成报告品牌」或「合成空白报告品牌」的版本、这两名账号的报告快照和对象元数据都是 0 行。浏览器没有单独打开只剩后继版本、没有品牌的页面；这两步写在页面分支中。
