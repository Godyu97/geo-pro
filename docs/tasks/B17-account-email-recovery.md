# B17 邮箱验证与密码找回

[Issue #17](https://github.com/Godyu97/geo-pro/issues/17) · [S-M0-01](../specs/M0.md#s-m0-01) · [T-M0-01](M0.md#t-m0-01) · [B06 冻结与恢复](B06-brand-deletion.md)

## 实现

- 登录页提供忘密入口，账户设置显示邮箱状态及验证入口，冻结品牌恢复页为未验证负责人提供返回原位置的验证链接。界面与邮件提供 zh-CN/en。
- 两种邮件请求独立按账号和来源 IP 计算滚动限额。验证邮件发送与重发共用 3 次/小时上限，找回为 5 次/15 分钟。请求先占用额度，再在响应后查找账号和投递；统一反馈只确认受理，投递失败可以用随机追踪标识查询脱敏日志。
- 邮箱验证链接为一次性随机令牌，有效 24 小时，数据库使用哈希标识。密码找回沿用 Better Auth 的一次性小时令牌、密码哈希及会话撤销。令牌只经邮件链接片段和同源确认请求传输。完成后移除片段，并提供安全返回入口。
- PostgreSQL 使用账号行锁协调旧密码登录和重设，SQLite 使用即时事务。重设成功后，旧密码和旧会话失效。品牌归属、冻结状态、恢复期限和冻结后近期登录要求由原处理器继续执行。后续受限入口可用 `hasVerifiedEmail(session.user)` 核对服务端会话中的验证状态。
- 两库新增一张 `auth_mail_rate` 表。账号与 IP 桶使用带动作命名空间的 HMAC，应用接受一次请求最多执行两条业务 SQL，同时占用两桶。过期索引供单独的一条有界清理 SQL 使用，每次最多删除 32 行。Better Auth 验证记录复用已有的标识索引。

## 配置与运行

`.env.example` 中的 `GEO_AUTH_MAIL_URL` 配置邮件网关，`GEO_AUTH_MAIL_SECRET` 为至少 32 字符的 Bearer 凭据。网关接收 JSON POST，字段为 `to`、`subject`、`text` 和 `traceId`。2xx 表示网关已接收。服务端要求 HTTPS，应用和网关均在回环地址时可以使用 HTTP 做隔离验收。网关请求有五秒超时并拒绝重定向。

`GEO_AUTH_MAIL_IP_HEADER` 指定可信入口写入的专用头。正式入口必须删除客户端提供的同名头，使用入口确认的单一 IP 覆盖，并禁止绕过入口直连应用端口。缺失配置或 IP 无效返回受控错误。网关日志不得留存消息正文、链接或凭据。

响应后投递依赖应用进程完成本次任务。进程在受理后退出时，用户可以在限额内重发。真实出站域名、供应商和网关部署，以及试点开放验收，均由 [Issue #21](https://github.com/Godyu97/geo-pro/issues/21) 核对。

## 验收记录

| 检查 | 实际结果 |
| --- | --- |
| 邮箱验证 | SQLite3 与 PostgreSQL 均通过 24 小时令牌有效期、篡改、重放、并发消费、跨账号和账号删除后重建的拒绝检查。 |
| 密码找回 | 两库均通过 1 小时令牌有效期、篡改、重放和跨账号拒绝。真实数据库写入失败时令牌与旧会话均保留。成功后旧密码、全部旧会话及并发旧密码登录留下的会话均无效，新密码可用。 |
| 限流与投递 | 两库均通过账号（含大小写归一）和 IP 的并发独立限额、滚动窗口、配置缺失及受控投递故障。已知与未知邮箱返回相同的受理合同；失败日志仅含流程、追踪标识及阶段。各库以 1,000 行合成桶核对主键、过期索引和每批 32 行的清理上限。 |
| B06、普通账户 | `pnpm verify:account-email` 和 `pnpm verify:brands` 通过。未验证用户可以登录和准备资料，直接恢复被拒绝。已验证但未在冻结后重新登录、旧会话和其他账号分别被拒绝。密码重设保留品牌冻结，已验证本人重新登录并显式恢复后才解冻。 |
| 双语言 | `pnpm check:i18n` 的 393 个消息 key 和 `pnpm test:i18n` 的 6 项通过。邮件专项用 Chrome 验证 zh-CN/en、375/768/1440、键盘、空值、重放反馈、语言切换和安全返回。原有 `pnpm test:e2e --max-failures=3` 的 73 项通过。 |
| 双库迁移及回归 | `pnpm db:auth-schema`、`pnpm db:generate`、`pnpm db:ddl`、`pnpm db:ddl:check` 通过。双方言均在上个迁移版本的隔离库运行 `pnpm db:migrate`。 `pnpm test:maintenance` 25 项及 `pnpm test:brands` 7 项通过，涵盖空库 DDL 对照。 `pnpm verify:maintenance` 在双方言分别运行的 `pnpm verify:auth` 全部通过。 |
| 工程与文档 | `pnpm lint`、`pnpm typecheck`、`pnpm build`、`python docs/tools/validate_docs.py` 和 OpenSpec 严格验证通过。 |

运行环境为 Node 24.22.0、pnpm 12.14.0、本机 Chrome 和随机隔离数据库。邮件接收器只监听回环地址。真实出站投递及试点开放条件由 #21 验证。
