# 品牌管理与 AI 品牌监测开发计划

2026-11-23。优先走通开发环境中一个获准品牌的建档、题集冻结、真实官方 API 采样和证据下钻。随后复用同一条链路验证持续计划与质量提醒。功能编号、指标和正式验收条件沿用 [M0 SPEC](../specs/M0.md)、[M1 SPEC](../specs/M1.md) 与 [指标合同](../07-指标与证据合同.md)。

## 品牌管理

| 场景 | 行为和验收 |
| --- | --- |
| 建档与恢复 | 负责人从品牌列表创建或继续保存中的草稿。可省略官网、别名和竞品。每个 M0 负责人只有一个活跃品牌。两种界面语言中断后均能恢复已保存的步骤 |
| 版本与权利 | 修改名称、别名、目标地区等实体信息生成新版本。历史回答和报告保留原引用。事实卡显示来源、授权范围、复核与补证状态，由负责人确认。内部原件只在有权范围内下载，容量不足时拒绝新上传 |
| 归档、冻结与导出 | 列表区分活跃、归档和冻结。删除前预览影响，冻结后限制读取与下载。恢复沿用身份复核和时效条件。旧下载在恢复后仍须重新生成。现有品牌缺保留策略记录时展示实际状态，避免回填接受同意 |
| 监测准备 | 品牌详情连接事实与题集，显示当前实体版本、已确认的自然发现题数、可用通道与额度状态。允许空官网并将官网引用标为不适用。事实审批用于内容门禁，采样仅发送冻结问题和已确认采样条件 |

建档的版本化保留告知复用 [#122](https://github.com/Godyu97/geo-pro/issues/122)，原件容量复用 [#123](https://github.com/Godyu97/geo-pro/issues/123)。演示观察与统计隔离复用 [#121](https://github.com/Godyu97/geo-pro/issues/121)。M1 的负责人转移与成员邀请沿用 [#128](https://github.com/Godyu97/geo-pro/issues/128)、[#129](https://github.com/Godyu97/geo-pro/issues/129)。

## AI 品牌监测

1. 确认同一品牌的实体、题集、通道和协议版本。快测沿用至少三道已确认非品牌题、最多十道核心题的合同，记录语言、目标地区、模式、重复次数及预算上限。缺授权、价格、资格或额度时显示原因。
2. 官方 API 复用 `officialSamplingPortFromEnv` 与现有运行、槽位和预算记录。服务端在请求前持久化尝试与金额预留，响应后独立记账。超时、崩溃或不明回执进入核对状态，重复请求只继续允许的槽位，保障费用安全。消费者入口沿用人工取证，并记录会话条件、时间、截图或可复查定位、实际耗时。
3. 官方回答经已有证据入口按槽位归档。用户能从概览追溯原文、引用字段、采样条件和判定版本。联网、提及、推荐和引用分别判定，条件未知与无分母如实展示。AI 判定草案由人员复核，纠正追加修订，原始回答保持可追溯。两条采样轨道各自展示，演示与探索样本按合同排除。
4. 用已验证的执行与证据链路接通持续计划。先验证一个到期窗口的官方槽位、暂停与预算控制，再以完整同口径窗口验证质量优先和趋势提醒。同一窗口重跑复用已有运行和站内告警。

## 开发环境真实联调

1. 使用现有开发数据库、Redis 和私有 S3，运行 `pnpm env:check`。需要模型连通性时加 `--probe-ai`。官方采样还需核对当前入口、模型版本、授权与实际价格。迁移在明确的开发库目标执行。
2. 在受控开发工作台用有授权的真实品牌名称、业务和可用公开资料走建档、事实维护、题集确认与版本回读。使用两个开发测试账号验证串品牌拒绝。生产准入条件由 #21 单独记录，开发邮箱校验沿用长期 Mock。
3. 在真实开发库中以最小获准预算试跑。M0 快测按合同确认至少三道自然发现题，核对一个官方渠道的真实回答、引用状态与费用。具备消费者入口授权时另做人工存证。记录可比较条件、失败及核对处置，从概览下钻至原文。涉及周期时使用真实到期窗口或明确标记为验证调度逻辑的隔离时钟。
4. 自动化回归继续在双库隔离数据、回环 AI/S3 mock 上测权限、并发、重试和故障。开发联调记录包含代码版本、环境代号、时间窗、运行/槽位/证据引用、模型与能力版本、经脱敏的调用次数、计费及失败分类。凭据、原始客户资料和签名链接留在授权环境。

Agent 自行在开发库确认数据与状态，按获准角色执行正式试点。品牌准入、真实通道和 M0 闭环分别由 [#21](https://github.com/Godyu97/geo-pro/issues/21)、[#31](https://github.com/Godyu97/geo-pro/issues/31)、[#32](https://github.com/Godyu97/geo-pro/issues/32) 跟踪。Agent 可先在已获准范围核验候选通道和实际预算，待官方执行和入证路径完成后联验在站使用。正式 API 10 题 × 2 轮、消费者 3 题 × 2 轮及阶段走查按 [M0 运行手册](../operations/m0-runbook.md) 与 [试点模板](../operations/m0-pilot-templates.md) 留证。
