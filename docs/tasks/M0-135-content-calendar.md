# M0-135 内容日历

2026-11-24。 [Issue #135](https://github.com/Godyu97/geo-pro/issues/135) · [视觉验收清单](../08-验收场景与样例.md#ui-visual-checks) · [S-M1-05](../specs/M1.md#s-m1-05)

品牌负责人打开内容日历后，应能先看到当前任务和下一步。有页面尚未核验时，先打开那条发布记录。已核验渠道保持核验结果，受阻渠道单独标出。没有品牌时前往品牌。读取失败时保留标题，不显示网址和发布编号，并用键盘重新载入。

基线 `5f765557a8658304e1b9e65eb786c175fa738329` 在隔离 Chrome 中文 375 像素复现。页面没有说明下一步。180 字无空格网址把表头挤成单字列，计划日和状态留在首屏之外。

- `/dashboard/content/calendar` 留在工作台唯一的 `main#main-content` 内。标题是内容日历。任务说明和计划日口径放在同一内容区。相关入口换行，包含返回内容和事实与材料。
- 仍有 `planned` 页面时，主要动作是打开尚未核验的发布，只出现一次，并指向按渠道排序后的第一条。已无待核验、但仍有 `blocked` 时，主要动作改为查看受阻发布。全部已核验或没有任务时，主要动作是返回内容。
- 受影响页面表在组件内横向滚动。表头不换行。长网址在页面列内换行，渠道、日期和状态保持整列。计划日不是上线日期。没有核验日时发布状态是未上线。
- 读取失败时标题仍是内容日历，提示可重试，主要动作是重新载入当前地址。不显示网址和发布编号。其他账号打开同一品牌地址仍是找不到页面。没有品牌时保留标题，主要动作是前往品牌。

## 隔离验收

Chrome 使用开发用回环 PostgreSQL、memory 缓存、回环 S3 和邮件 Mock。品牌、事实、稿件和发布编号都是合成数据。本轮没有请求供应商。生成使用隔离模板，不调用付费模型。事实在发布后撤销，再按撤销原因打开维护任务。

| 场景 | 实际结果 |
| --- | --- |
| 尚未核验 | `zh-CN` 与 `en` 在 375、768、1440 像素无横向溢出，且只有一个 `main`。中文可见「有页面尚未核验。计划日不是上线日期。先打开尚未核验的发布记录。」主要动作「打开尚未核验的发布」只出现一次，375 像素在视口内，指向 `site` 发布。渠道 `site` 与 `zhihu` 都在，计划日是 `2026-11-01`，状态是计划中，发布状态是未上线，核验日是尚未核验。180 字网址留在页面列内。中文 375 像素用 Enter 打开 `site` 发布。 |
| 受阻渠道 | 把 `site` 记为已核验、`zhihu` 记为受阻后，同一两种语言和三种宽度无横向溢出。中文任务说明写明已核验渠道保持结果，受阻渠道单独标出。主要动作是「查看受阻发布」，375 像素在视口内，指向 `zhihu`。`site` 仍是已核验，核验日 `2026-11-20`，发布状态是已按核验日上线。`zhihu` 是受阻且未上线。没有「打开尚未核验的发布」。 |
| 读取失败 | 英文 375 像素保留标题 Content calendar 和失败提示，看不到两条网址和两个发布编号。重新载入在视口内。清除故障标记后用 Enter 回到原日历，受阻说明和长网址仍在。 |
| 无品牌 | 另一个临时账号在 375 像素下，中文显示「前往品牌」，英文显示 “Go to brands”，两种语言都无横向溢出。 |
| 其他账号 | 英文 375 像素显示 Page not found，看不到长网址和发布编号。 |

六张 375 像素截图使用合成数据，保存在本地 `.cache/issue-135/content-calendar/`，可由 `tests/e2e/content-calendar.spec.ts` 重新生成。清理后回读，邮箱前缀 `content-calendar-` 的账号、名称为「合成日历品牌」的版本、对应合成网址的发布记录和维护页都是 0 行。本轮浏览器没有单独打开全部已核验或没有维护任务的日历；这两步写在页面分支中。
