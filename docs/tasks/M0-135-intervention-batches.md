# M0-135 干预批次

2026-11-24。 [Issue #135](https://github.com/Godyu97/geo-pro/issues/135) · [视觉验收清单](../08-验收场景与样例.md#ui-visual-checks) · [S-M1-06 和 AC-M1-06-3](../specs/M1.md#s-m1-06)

品牌负责人打开 `/dashboard/reports/interventions` 时，可以从页首保存首个批次、进入最近的未生效批次登记或更新页面，或在所有批次均生效后查看最近一批的核验明细。页面沿用报告区的位置提示、共享按钮和输入框。页内链接把键盘焦点带到页面键字段或批次状态标题。长页面键留在卡片内换行。生效点规则可用键盘展开。

基线 `c599ad38a94c2a6187b1a1af56d41630062a3b12` 在隔离 Chrome 中文 375 像素下复现。空态排在创建表单之后，缺少先保存批次再登记页面的说明。

## 隔离验收

Chrome 使用回环开发 PostgreSQL、合成品牌和独立临时账号。故障注入在测试源码副本中。页面键和 UTC 时间均为合成输入，仅作批次核验与回读。供应商调用和外部页面抓取均为零。

| 场景 | 实际结果 |
| --- | --- |
| 首个批次 | `zh-CN` 与 `en` 在 375、768、1440 像素都保留报告位置和唯一的 `main`。页面无横向溢出，主要操作在视口内。中文 375 像素按 Enter 保存批次。接口回读 `pending`、`effectiveAt = null`、页面数为 0。 |
| 三页待核验 | 用 Enter 打开登记，焦点移到页面键。登记三页后仅回填前两页，接口回读第三页的核验时间和整批生效点均为空。两种语言和三种宽度可见未生效与一条未核验，273 字符页面键留在卡片内，主要操作在视口内。 |
| 输入失败及恢复 | 中文 375 像素用 Enter 提交 `2026-11-04` 后，页首显示 UTC 校验提示。接口回读与提交前一致。改填 `2026-11-04T14:00:00.000Z`，三页均完成核验，状态为 `effective`。 |
| 核对生效点 | 三页时间依次为 `2026-11-02T12:00:00.000Z`、`2026-11-06T13:00:00.000Z`、`2026-11-04T14:00:00.000Z`。页面和 API 均使用最大值 `2026-11-06T13:00:00.000Z`，符合 AC-M1-06-3。两种语言和三种宽度结果一致，页首操作在视口内。英文 375 像素可用 Enter 查看批次并聚焦状态标题，也可展开生效点规则。 |
| 读取失败 | 英文 375 像素注入读失败后保留标题和可重试提示。品牌名、页面键、生效点、批次 ID 和内部错误未出现在页面中。解除故障后按 Enter 重新载入，接口回读与故障前一致。 |
| 隔离与清理 | 第二账号在两种语言和三种宽度只看到建档操作及返回报告，读取或修改同一批次的 API 都返回 404。清理后按临时账号和品牌编号查询，账号、品牌及版本、批次与页面记录为零。 |
