# M0-135 监测运行详情

2026-11-24。 [Issue #135](https://github.com/Godyu97/geo-pro/issues/135) · [视觉验收清单](../08-验收场景与样例.md#ui-visual-checks) · [S-M0-05](../specs/M0.md#s-m0-05) · [指标与证据合同](../07-指标与证据合同.md)

品牌负责人从运行确认页登记或重开运行后，可在首屏看到采样轨道、计划分母、进度和主要操作。基线 `53500f7dbaaf7b177d9ad66ab90712904d3978b5` 在迁移后的临时 PostgreSQL 上复现了布局缺口。Chrome 375 × 900 中刚登记的官方轨道运行能找到「执行官方采样」，但按钮在视口内的可见比例为 0，新增断言失败。

## 交付范围

- `/dashboard/monitoring/runs/[runId]` 复用工作台的白色面板、按钮和状态标签。待处理的官方运行突出执行操作，并关联费用确认说明。已有结果可直接跳到槽位和回执。返回入口保留当前品牌。
- 冻结范围、预算与回执各有区域。宽表在局部滚动，键盘可将焦点移到表格区域并横向滚动。请求联网仍来自冻结运行，实测触发来自回执，费用仍按供应商尝试状态展示。原文和证据入口沿用既有读回。
- 加载、读取失败、缺失或跨账号运行保留同一个页面标题。读取失败可重试当前地址并保留支持定位编号。缺失和跨账号使用相同提示，返回默认运行确认入口。执行、费用与归属仍由既有服务端规则处理。

## 开发库实测

- `pnpm env:check` 通过 15 项，覆盖回环开发 PostgreSQL、Redis 和 S3 写读清理。使用允许名单内负责人的已登记运行，在只读事务中通过既有读取命令核对 [官方执行](M0-131-official-run-execution.md) 和 [官方入证](M0-133-official-evidence.md) 的 `db6cb290` 记录。计划及成功各 3，题集和通道版本均为 2，目标地区 `CN`、业务语言 `zh-CN`、请求联网 `off`，三条回执均为 `not_triggered` 和完整空引用。原文 SHA-256 与证据编号均匹配，三条已知费用合计 CNY 0.03。
- `pnpm start --hostname 127.0.0.1 --port 3125` 使用生产构建和开发服务。Chrome 375 像素下用临时账号访问随机运行和已有的跨账号运行，两种语言下 API 均返回 404，界面均显示同一恢复提示和一个主要内容地标。Enter 可返回运行确认。临时账号及会话已删除并回读确认。本轮开发联调未发起供应商调用。
