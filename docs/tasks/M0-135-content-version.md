# M0-135 稿件版本

2026-11-24。 [Issue #135](https://github.com/Godyu97/geo-pro/issues/135) · [视觉验收清单](../08-验收场景与样例.md#ui-visual-checks) · [S-M0-10](../specs/M0.md#s-m0-10)

品牌负责人打开稿件后，应能先看到当前任务和下一步。待审草稿先提交审核，审核中可以批准，已拒绝或批准失效后可以再次提交。当前批准仍有效时，下一步是运行预检。读取失败时保留标题，不显示稿名、正文和批准指纹，并用键盘重新载入。

基线 `605ea9f00645183a3b5dafcf2ee343719afd87c2` 在隔离 Chrome 中文 375 像素复现。180 字无空格标题占据页首，页面没有「稿件详情」，也没有说明下一步。提交审核排在渠道和指纹之后。

- `/dashboard/content/versions/[versionId]` 留在工作台唯一的 `main#main-content` 内。标题是稿件详情。任务说明、已保存状态和稿件编号放在同一内容区。相关入口换行，包含返回稿件列表、渠道变体、事实与材料和资料原件。
- 状态为 `draft`、`rejected` 或 `invalidated` 时，主要动作是提交审核。`in_review` 时是批准（自审），拒绝只在渠道信息后出现一次。`approved` 且当前指纹仍匹配时，主要动作是运行预检，导出区不再重复该按钮。归档只读时不提供这些写入动作。
- 稿名在标题区换行。正文、渠道和批准指纹留在内容区内。状态仍显示已保存的值。生成不会把草稿写成已批准。
- 读取失败时标题仍是稿件详情，提示可重试，主要动作是重新载入当前地址。不显示稿名、正文、长页面地址和批准指纹。其他账号打开同一地址仍是找不到页面，看不到这些内容。

## 隔离验收

Chrome 使用开发用回环 PostgreSQL、memory 缓存、回环 S3 和邮件 Mock。品牌、事实、Brief 和稿件编号都是合成数据。本轮没有请求供应商。生成使用隔离模板，不调用付费模型。

| 场景 | 实际结果 |
| --- | --- |
| 待审草稿 | `zh-CN` 与 `en` 在 375、768、1440 像素无横向溢出，且只有一个 `main`。中文可见「这篇稿件仍是待审草稿。先提交审核；生成不会自动批准。」主要动作「提交审核」只出现一次，375 像素在视口内。没有批准或拒绝。状态是 `draft`。180 字标题留在标题区内。正文含合成长页面地址。 |
| 审核中 | 中文 375 像素用 Enter 提交后，状态为 `in_review`。同一两种语言和三种宽度无横向溢出。任务说明写明批准不等于公开发布。主要动作是批准（自审），375 像素在视口内。「提交审核」消失。拒绝只出现一次。 |
| 读取失败 | 英文 375 像素保留标题 Version detail 和失败提示，看不到长标题、批准指纹、正文框和长页面地址。重新载入在视口内。清除故障标记后用 Enter 回到原稿件，状态仍是 `in_review`，长标题仍在。 |
| 其他账号 | 英文 375 像素显示 Page not found，看不到长标题、稿件编号和长页面地址。 |

六张 375 像素截图使用合成数据，保存在本地 `.cache/issue-135/content-version/`，可由 `tests/e2e/content-version.spec.ts` 重新生成。清理后回读，邮箱前缀 `content-version-` 的账号是 0 行，名称为「合成稿件品牌」的版本是 0 行。本轮浏览器没有单独打开已拒绝、批准失效或已批准稿件；这些状态的下一步写在页面分支中。隔离主流程仍能保存变体、提交审核、自审批准、预检并导出。
