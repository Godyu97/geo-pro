# Issue #166 确认替代版本时的依赖与撤销选择

2026-11-26。 [Issue #166](https://github.com/Godyu97/geo-pro/issues/166) · [公共 SPEC 第 5 节](../04-产品功能规格-SPEC.md) · [S-M0-02](../specs/M0.md#s-m0-02)

品牌负责人在批准一条与当前有效事实冲突的新版本之前，能看到仍引用旧版的稿件版本、渠道变体和已关联发布，并明确选择立刻撤销旧版，或让旧版继续有效到原定到期。不勾选 T-M0-02，也不勾选 T-M1-05。维护任务沿用 [T-M1-05 已交付行为](M1-157-content-maintenance.md)。

## 交付范围

- `/dashboard/brands/[id]/facts` 在冲突仍存在时列出旧版依赖。三类都为空时分别显示空列表。列表含稿件标题和状态、变体渠道、发布网址，不含正文。另一账号读取工作台得到不存在，按对方身份查询依赖得不到标题或正文。
- 不勾选立即撤销时，新版可以批准，旧版保持已批准，稿件状态不变，不新建维护任务。
- 勾选立即撤销时，旧版变为已撤销，并与单独撤销使用同一条开放维护任务：有关联发布才建任务，再次批准不另建任务。影响链带上该发布对应的稿件和渠道变体。没有关联发布的稿件不进入维护页。
- 只新增一条不冲突的事实时，不撤销其他已批准事实，也不改变历史稿件数量。
- 中英文都显示选择和空列表。不改已导出交付包，也不表示外部页面已被远程撤下。双人审核开启时仍拒绝提交人自批。

## 实测记录

| 检查 | 结果 |
| --- | --- |
| 环境 | 隔离库由 `tests/maintenance/helpers.mjs` 创建并清理。浏览器走查使用 Playwright 临时 PostgreSQL 与回环服务，账号在结束时清理。 |
| 隔离行为 | `pnpm test:brand-facts` 10 项通过。双方言各覆盖：两篇草稿和一条发布在不撤销时旧版仍为已批准、稿件状态保持 `draft`、维护任务为 0，页面数据仍列出这两篇稿件和这条发布；勾选撤销后旧版为已撤销，开放维护任务 1 条，影响链含该发布的稿件、变体和网址，再次批准不新增任务；无发布的冲突撤销不另建任务；不冲突的新事实不改变其他已批准事实和历史稿件数量。依赖响应不含稿件或变体正文。另一账号的工作台读取为不存在，按其身份查询依赖为空。 |
| 查询计划 | 上述测试在 2 篇关联稿件上记录依赖查询计划。SQLite 先用 `content_version_owner_idx`，再以 `brand_fact_use` 主键覆盖索引核对事实版本。PostgreSQL 为 Nested Loop：`content_version_owner_idx` 连接 `brand_fact_use` 主键只读扫描。这是该夹具规模的实际计划，不是生产延迟结论。 |
| 回归 | `pnpm test:content` 54 项通过。 |
| 静态与构建 | `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过。`pnpm check:i18n` 3852 个键一致。 |
| 浏览器 | `pnpm exec playwright test tests/e2e/brand-facts.spec.ts` 1 项通过。中文 375 宽录入冲突新版，三类依赖都显示空列表，撤销选择默认未勾选。英文 1440 与中文 768 无横向溢出。不勾选撤销并批准后，新版与旧版都仍为已批准，空依赖列表仍在。随后原有键盘撤销、越权拒绝和读取恢复仍通过。 |

未连接外部 CMS，也没有远程撤下任何外部页面。T-M0-02 与 T-M1-05 勾选不在本记录范围内。
