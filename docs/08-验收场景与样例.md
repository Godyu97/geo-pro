# 验收场景与样例

> v3.0｜产品验收设计；并非已运行的软件测试。功能验收共 78 项，分别位于各级 SPEC；阶段验收另见 05。

## 1. 合成品牌与主流程

演示品牌“北岸设备”，网站使用保留示例域名 https://beian-equipment.example；竞品“远帆设备”。所有记录 is_demo=true，页面和导出标“演示数据”。

准备三个非品牌题：“30 家门店如何管理设备巡检？”“支持离线巡检的设备管理产品怎么选？”“预算有限的连锁门店怎样比较报修系统？”以及一个比较题“北岸设备和远帆设备有什么不同？”。比较题不进自然发现主指标。

准备三条事实：支持离线巡检（附合成产品说明）；价格按门店数报价（附条件及合成报价说明）；服务范围（附日期）。这些只是测试事实，不得用于真实营销。

走查：建档 → 题集预览 → API fixture 运行（3 成功 1 失败）→ 消费者 fixture 人工存证 → 原文与独立标签 → 一项 FAQ 缺口任务 → 确认事实与 Brief → 两篇成功一篇失败的小批次 → 重试失败项 → 逐稿审核 → Markdown/HTML 包 → 草稿链接核验失败 → 合成公开页核验 → 同范围复测 → 报告 HTML/JSON。

这条路径覆盖局部失败恢复，仍需用真实渠道/真实试点单独执行阶段门禁。不能将示例网站当作真实发布目标。

## 3. 机器样例如何使用

- [metric-cases.json](fixtures/metric-cases.json)：10 个金样，包含分层分母、归属未知、零分母、题等权、共同题、质量门槛、线索去重、日期窗口和独立标签。
- [report-example.json](fixtures/report-example.json)：三个共同题、前后各一次、推荐 0/3→1/3 的演示快照；值可从逐题记录复算。所有 observation 和 content ID 为显式合成引用。

新项目需要另做真实持久化、页面、权限及外部能力验证；本目录检查脚本只复算其中的数学/日期案例，并核对引用、ID 和依赖。语义分类两例作为业务验收输入，由实现与人工复核测试，而非让文档检查脚本冒充模型分析测试。

## 4. 状态与错误的人工走查

各主要页面检查首次空态、加载、无匹配、部分成功、权限失效、预算不足、外部能力不可用、未知引用、历史版本和证据被删除。检查返回列表的筛选保留、刷新后的运行进度、批次取消后的晚返回、待核对费用处理。

375px 检查主要按钮可点击、表格可横向查看；768px 与 1440px 检查不遮挡状态/分母；键盘可完成引导、筛选、原文展开、审核与导出。不用装饰图片或过量动效掩盖数据质量提示。

## 5. 外部验证记录模板

| 字段 | 应记录内容 |
| --- | --- |
| 能力/版本 | 观察对象、入口、模式、采集方式、模型版本或未知 |
| 验证条件 | 时间、目标/实际地区、会话、联网要求、账户可用权限 |
| 执行范围 | 固定题集、槽位数、成功/失败/未知、实际耗时 |
| 证据 | 原回答、引用完整性、联网发生依据、消费者存证 |
| 费用 | 预计上界、实际、待核对；不要写密钥/账号密码 |
| 结论 | 哪些能力通过、哪些不支持、何时过期、退化处理 |

## 6. 文档包检查

运行 `python docs/tools/validate_docs.py`。检查器只用标准库，迁移到新项目仍可使用。其通过意味着本包的链接、追溯、依赖和算例自洽，不证明真实产品已实现。

## 7. 双语言兼容矩阵（ui-i18n-v1）

这是 [公共多语言合同](04-产品功能规格-SPEC.md#interface-locales) 的验收设计，实施时执行并记录实际结果；当前均未进行运行时验证。矩阵与现有功能验收配合，不增加 78 项功能验收的计数。M0 起所有有界面的交付均适用，后续新增页面继续覆盖。

| 场景 | 操作与范围 | 预期结果 |
| --- | --- | --- |
| 两种语言完整度 | `zh-CN` / `en` 分别走官网、账号、工作台及已开放功能的正常/空/加载/失败状态 | 文案、校验、图例、费用提示、页面标题及 ARIA 文本完整；无缺 key、空译文、占位参数或意外中文回退 |
| 默认、选择与恢复 | 无偏好首次访问、显式选择、刷新、重新访问、无效 locale 与浏览器语言不受支持 | 有效选择被记住；无偏好按解析规则，无法匹配回退 `zh-CN`；当前语言清楚，无循环或空白页 |
| 路由与会话 | 深链接、登录/退出/回调、前进后退、404/错误页；在筛选和草稿存在时切换 | 身份与归属检查保持，返回路径/筛选/草稿保留；切换不重复提交、采样或收费 |
| 服务端与客户端一致 | 两个 locale 分别直接请求首屏、刷新并触发客户端交互；交替或并发请求两种语言 | `<html lang>`、Metadata、首屏、显式 `Intl` 格式与交互语言一致，无 hydration 错误或跨请求串语言；SSR/HTTP（`Vary`）与本地化缓存不混用 |
| 业务 scope 与数值 | 结合 AC-M0-07-3 切换界面语言，核对既有题集/采样语言、原文、分子分母与历史报告 | 原始证据与冻结 scope 不变，API/消费者轨道仍隔离；翻译标签不改变指标或快照字节 |
| 格式化与输入往返 | 固定时间、CNY 金额、百分比、0/1/多个数量、中英文及混合名称、IME 输入法组合回车、长 URL；保存后重开和导出 | 显示符合 locale，币种/业务时区/数值精度保持；校验规则与字数限制一致，IME 回车不误提交，Unicode 原文与非 ASCII 导出文件名可往返，无乱码或按展示字符串计算 |
| 响应式与键盘 | 两种语言分别覆盖 375/768/1440 宽度、长英文及无空格长词/URL、弹窗、表格、图表图例/坐标轴和键盘导航 | 无截断关键操作、图表重叠或遮挡状态，长文本可换行或可访问查看，焦点与可访问性名称正确 |
| 缺失消息与外部错误 | 故意移除译文或改变插值参数；模拟未知服务端错误与不可用语言资源 | 开发/交付检查发现缺失；运行时给安全回退并记录定位信息，无内部异常或 key 泄漏，回退不计英文通过 |

字典 key/参数检查、页面集成和浏览器走查的实际命令在实现时补齐。文档检查器不会执行以上流程，也不验证英文翻译质量。
