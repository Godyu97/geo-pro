# M0–M2 里程碑与验收计划

> v3.0｜2026-11-17｜按可交付用户价值分级，不继承旧项目人日、团队规模和固定周数。

## 1. 阶段边界

| 级别 | 完整交付 | 明确不含 | 开始与结束 |
| --- | --- | --- | --- |
| M0 | 单品牌真实测量、证据、建议、事实、内容、人工发布核验、探索复测与报告 | 团队/订阅/连接器/批量自动发布 | T-M0-01 起；T-M0-GATE 通过方可称真实 MVP |
| M1 | 周期监测、竞品来源、纠错、资产、多渠道维护、正式观察、线索、团队 | 代理商结算和无人审核外部动作 | M0 通过且需求信号成立；T-M1-GATE |
| M2 | 辅助采集、授权连接、代理交付、持续数据接入、受控助理、行业扩展 | 洗稿、风控绕过、固定排名保证、无限自主执行 | M1 通过且具体授权/场景成立；T-M2-GATE |

M0 可按“建档与题集 → 真实采样 → 证据与诊断 → 内容与交付 → 核验与复测”交付纵向切片。M1/M2 按依赖表执行。并列依赖不是要求启动多个 agent；团队根据新项目实际容量安排。

## 2. 阶段门禁（可写入发布验收）

Agent 自行使用开发数据库、获准账号及真实服务执行正式试点并逐项留证。产品内事实确认、审批和发布仍由具备对应权限的角色执行，Agent 用获准试点账号操作。开发邮件采用长期 Mock；生产投递与上线另按生产发布条件记录。

### AC-M0-GATE

Given M0 的 12 个功能任务全部实现，When 用一个经授权真实试点品牌走通以下旅程，Then 满足全部条件才通过：

1. 建档、至少 3 个非品牌题、事实确认、费用预览和身份隔离可用。
2. 至少一个官方 API 完成 10 题×2 轮的能力验证，保留完整/缺失引用、失败和费用说明；至少一个消费者入口完成 3 题×2 轮人工存证。外部可得性不足时可以完成本地软件验收，但该门禁保持阻塞。未验证联网只交付相应非联网/未知层，不能宣称联网监测通过。
3. 同一个试点品牌至少 3 个共同非品牌题在实际采用的同一轨道各完成一次前后采样，满足 M0 探索可比条件；另一个轨道也有真实证据但不强制做跨轨结论。
4. 从真实回答/页面证据创建至少一个任务，确认必要事实，生成或编辑一篇有主张绑定的内容，显式审核并导出正式包。由获准的试点发布角色在授权页面完成发布或提供试点发布凭据，再核验真实页面和执行复测。可比较的改善、持平与下降结果均按实际记录。
5. 78 个功能验收中的全部 M0 36 项以及 08 文件中的共同关键场景通过；数学金样、越权、预算、原文不变、审批失效、草稿不算发布必须通过。按 [双语言兼容矩阵](08-验收场景与样例.md#i18n-checks) 分别完成 `zh-CN` / `en` 的完整度、切换、首屏/刷新、布局及业务语义隔离验证，不能用单语言或回退结果代替。
6. Agent 在开发环境以五次独立浏览器会话走查，至少四次完成建档和监测范围确认，操作时间中位数不超过五分钟（去除外部等待），至少三次从指标下钻到原文并创建带证据任务。分别记录场景、实际用时、失败和复验。该组数据标为 Agent 走查。
7. 输出运行/支持手册、真实能力清单、未知项、数据保留/删除行为和成本记录。执行新项目所需质量检查，报告实际命令与结果。

这是一条实际内容闭环的门禁，不要求 M0 等待正式 14 天基线或 D+28。用户选择 D+7 路径时须等窗口到期，不能用合成日期宣布真实观察完成。

### AC-M1-GATE

Given M0 通过、8 个 M1 功能任务完成，When 用真实持续计划和团队角色执行至少一个正式观察批次，Then：

- 全部 24 项 M1 功能验收通过；持续计划覆盖部分失败、暂停、预算不足和能力退化。
- 自动分析使用至少 200 条已获准的真实回答，以原文按规则独立标注并冻结基准，覆盖同名/别名、否定推荐、比较、空/缺失引用及受限页面；至少 60 条保留作未参与调整的验收集。Agent 先冻结参考标注，再对照待测输出。争议使用两次独立判读取证并保留标注版本，无法确认的争议单列。实体识别精确率至少 95%、召回率至少 90%；原生引用抽取 TP/(TP+FP+FN) 至少 98%，并列精确率和召回率。无正例类别为 N/A。
- Agent 使用两种独立的获准成员身份验证职责分离，验证撤销后正文和文件不可访问。
- 一次事实变化能定位全部受影响渠道版本，完成一条维护修复与再次核验。
- 冻结的基线、实际生效点和至少 D+7 完整窗口符合指标合同，或在无法满足时清楚维持“正式观察未完成”；门禁不能用探索报告替代。
- D+14/D+28 软件逻辑可用固定时钟测试，但真实后续检查点单列 pending，不伪称全周期结项。
- 至少一次真实来源业务反馈或经授权导入验证，缺分母不生成转化率；没有咨询可如实零记录，仍需验证导入与来源边界。
- M1 新增与调整的页面、站内提醒、竞品/来源面板、成员权限交互及导出继续满足 [ui-i18n-v1](04-产品功能规格-SPEC.md#interface-locales) 并按 [双语言兼容矩阵](08-验收场景与样例.md#i18n-checks) 分别完成 `zh-CN` / `en` 验收。

### AC-M2-GATE

Given M1 通过、6 个 M2 功能任务完成，When 对已经开通并授权的具体场景执行验证，Then：

- 全部 18 项 M2 功能验收通过；至少一个辅助采集入口、一个草稿连接、一个数据源连接有真实验证记录。
- 跨品牌委托、到期、撤销、在途结果未知及对账可以解释和恢复；外部动作不重复。
- 代理交付至少覆盖两个被授权品牌，报告、素材和账单不可串客户；真实收费未接入时保持登记模式。
- Agent 验证经营助理的 5 项上限、预算与逐项确认，并用至少一个获准真实行业或本地场景完成走查。
- 公开发布、支付、外部通知如未完成具体平台能力验收，则保持对应能力关闭，不因 M2 整体完成而宣称全平台可用。
- M2 新增与调整的页面、代理组合/账单视图、连接预览及白标/导出报告继续满足 [ui-i18n-v1](04-产品功能规格-SPEC.md#interface-locales) 并按 [双语言兼容矩阵](08-验收场景与样例.md#i18n-checks) 分别完成 `zh-CN` / `en` 验收。

## 3. 验证分层

| 层 | 何时执行 | 主要证据 |
| --- | --- | --- |
| 纯业务合同 | 每个涉及指标/状态/权限的任务 | 金样计算、合法/非法状态、版本失效与预算边界 |
| 功能集成 | 对象之间开始关联时 | 保存后重开、重复动作、撤销与批量操作、失败恢复 |
| 主流程走查 | 每个纵向切片与阶段门禁 | 真实或显式 fixture 完整路径、375/768/1440 视口、键盘 |
| 外部能力验证 | 首次启用、过期或发生变化 | 账号权限、时间、来源、原始证据、引用完整性、费用 |
| Agent 正式试点 | 对应软件、数据与通道可用之后 | 独立走查的耗时与完成结果、实际内容与复测、通道回执及成本 |

默认自动验证不产生外部费用；真实验证使用已授权范围及硬预算。当前文档工作没有执行上述产品测试。

## 4. 完成记录与阻塞分类

每项标 planned/in_progress/software_verified/live_verified/blocked/done，并记录验收 ID。done 意味该任务适用验收已完成，不是“代码写完”。真实外部门禁没有验证时只能 software_verified，阶段 GATE 不能勾选。

阻塞记录具体缺少的授权材料、账号能力、可信预算、软件前置、数据质量或自然观察窗口，以及可复核的解除条件。Agent 同时推进可独立执行的步骤。

## 5. 估算与排期方式

在新项目完成 T-M0-01 和 T-M0-04 的最小检查后，按每个任务估算开发/验证投入和外部等待，给区间与假设。正文不预设人数、框架或工期。内容制作、人工采集和复核单独记工时。正式观察周期从合格基线与实际生效点计算，不从项目开工日倒推。
