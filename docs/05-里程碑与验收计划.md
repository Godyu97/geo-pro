# M0–M2 里程碑与验收计划

2026-11-26 二期评审。产品在现有开发环境做正式业务验收。二期按[各模块首版成果](tasks/phase-2.md)排工单，M0/M1/M2 用于汇总产品覆盖范围。单个功能按直接软件依赖开工和验收；任务表与机器索引中的跨阶段 GATE 依赖只用于整阶段交付声明。

## 每个功能怎样算可用

从用户实际会打开的页面开始，用自己的登录身份操作，保存后重开能看到正确结果，并能进入下一步。涉及权限时，用有权和无权账号各验证相关动作。涉及采样、文件和外部连接时使用实际配置的服务并保留脱敏定位。只验证本功能用到的通道、授权和预算。长期邮件 Mock、隔离单测和破坏性回归沿用工程约定。

在 Issue 记录入口、实际操作、结果和证据位置。如果某个连接不可用、某次调用缺费用上限或某个窗口未到，标明具体未验证动作，继续能执行的模块。生产部署另按发布授权执行。适用工程检查见[开发文档入口](README.md)。

## 阶段结果如何汇总

### AC-M0-GATE

普通用户从首页建品牌、确认题集，通过一个可用真实通道发起监测。从原文创建任务、确认事实、完成一篇内容的审核和导出，回填已获授权的公开页面，核验后进行同口径复测并打开报告。用同一品牌的运行、回答、发布和报告编号回读这条路径。其他通道按实际验证状态列出。

### AC-M1-GATE

在开发工作台用真实品牌保存持续计划，查看到期运行、质量与竞品，组内成员按品牌权限协作一次，并从一次内容维护或实际业务反馈追溯到报告。正式效果结论使用指标合同所需的真实基线与到期窗口；尚未到期时报告显示等待观察。分析精度评测随相应能力验证。

### AC-M2-GATE

用已开通的受托品牌或真实连接完成一项客户交付，能回读所用快照、交付结果和授权范围，撤销后停止后续访问。在助理或行业模块验证用户选定的真实场景。采集、发布、通知和支付分别记录实际开通及实测范围。

三项阶段记录沿用原 ID 和任务表。整阶段结项时逐项核对其声明范围和功能验收；已通过的开发环境记录直接复用。同一功能已有业务证据时，无需再安排另一套试点。趋势、引用和效果的计算遵守[指标与证据合同](07-指标与证据合同.md)。一期报告中的试点轮数、走查次数和招募数量用于回看一期，二期不把这些数量设为开工或通用验收条件。
