# Web 多语言设计与兼容规范

> 2026-11-17｜产品合同：ui-i18n-v1｜首期支持 `zh-CN` / `en`，默认 `zh-CN`｜状态：需求已确认，运行时适配待实施。

产品行为以 [公共多语言合同](../04-产品功能规格-SPEC.md#interface-locales) 为准；本文件规定 Web 实现边界与维护方式。适用于页面、组件、导航、表单、错误、图表、Metadata、展示格式及相关缓存，不因两种语言建立两套业务流程。

## 当前事实与接入范围

当前 `src/app/layout.tsx` 固定 `lang="zh-CN"`，Metadata、认证表单、校验和导航使用中文文案。仓库没有消息目录、语言选择/持久化、英文界面或专用 i18n 验证入口；不得将已有中文页面视为双语言交付。

首期覆盖已开放的官网、登录/注册、工作台壳层及后续逐项实施的业务界面，包括空态、加载、异常、校验、权限/费用提示、可访问性名称和页面标题。语言支持是 M0 起的公共要求，不后置到 M1/M2；本次只补充合同与规范，不实施页面或安装依赖。

## 界面语言与业务语言分离

| 语义 | 由谁确定 | 必须保持的边界 |
| --- | --- | --- |
| 界面 locale | 当前请求解析出的 `zh-CN` 或 `en` | 控制界面消息和展示格式，不作为监测 scope 的语言 |
| 品牌/题目/采样语言 | 用户明确的业务配置与冻结版本 | 改变时走既有版本和可比性规则，不跟随界面切换 |
| 内容目标语言 | Brief/内容版本的明确要求 | 翻译内容属于新版本并重新审核，不由切换界面触发 |
| 报告/导出展示语言 | 生成时明确并记录 | 标签可本地化；原始证据、内容指纹与已导出快照保留原字节 |
| 币种、统计时区与地区 | 真实金额及业务协议 | 使用真实币种与冻结时区，M0 日统计仍按 Asia/Shanghai；英文界面不隐式换为美元或其他地区 |

用户名称、品牌名称、问题、回答、来源片段和 URL 以原文存取。翻译展示若另行提供，需明确标注并保留原文；不得替换事实或观察原文。机器状态码、ID、错误码与 API 字段保持稳定，翻译只作用于展示消息。特别地，品牌建档（如 `S-M0-01`）中的“目标地区（默认中国大陆）/ 目标语言（默认简体中文）”属于业务监测目标配置，即使在 `en` 界面下其业务默认值仍独立于界面 locale，仅字段标签与选项文案随界面语言展示。

## locale 解析、切换与路由

- **单一白名单**：支持集合集中定义为 `zh-CN` / `en`，默认 `zh-CN`；上游 URL、Cookie、偏好和语言头均视为输入，规范化后只接受白名单值。英文浏览器地区变体可显式归并为 `en`，其他映射须集中定义和核验；未知或不可用值回退 `zh-CN`。
- **优先级明确**：若采用 locale URL，以有效 URL locale 为准；否则依次使用已记住的显式选择、受支持的浏览器偏好、默认值。首屏在服务端完成解析，浏览器偏好不能覆盖用户已保存的选择。
- **完整切换**：提供可访问的“简体中文 / English”选择，明确当前项。切换只更新界面偏好，保留身份、当前资源、筛选和未提交草稿；刷新、深链接和前进/后退的语言行为一致，不隐式提交表单或重新启动收费操作。
- **路由、错误边界与鉴权兼容**：集中处理导航链接与返回地址，覆盖登录前后、退出、`not-found`、`error.tsx`、`global-error.tsx`、`loading.tsx` 及回调。语言参数不改变资源权限；跳转目标仍需校验，不能产生循环、开放重定向或丢失筛选。不要为了 locale 前缀直接改写 Better Auth 和其他机器 API 路径；Better Auth 返回的错误码与前端表单校验（如当前 `auth-form.tsx` 中的错误映射与 `validation.ts`）须转为稳定校验/错误码并按当前 locale 映射提示，不能直接透传未翻译的框架消息。
- **选型边界**：是否使用 locale 路径、Cookie/账号偏好及具体 i18n 库在实施时记录；优先复用现有能力，只引入必要依赖，不为两个 locale 提前新增复杂偏好表或全局状态框架。

## 消息、校验与安全输出

- 用户可见文本通过集中消息目录与稳定语义 key 管理；两种语言的 key 与插值参数必须一致，使用类型约束或可执行检查发现遗漏。新增页面同步提供两种语言，不在组件中散布中英文三元分支。
- 翻译完整句子，数字、实体名称等作为参数；避免拼接句子或假定英语单复数与中文相同。按用例使用所选方案支持的复数规则，正确处理 0、1、多个和缺值。
- 表单标签、占位、提示、客户端与服务端校验、Toast、图表图例/tooltip、按钮、空/失败状态、ARIA 标签和 Metadata 均在覆盖范围。校验规则与错误码保持一致，仅消息按 locale 映射；未知服务端错误显示对应语言的安全通用提示，不原样透传内部异常。
- 开发与交付检查发现缺 key、空译文或插值不匹配应失败并补齐；运行时意外缺失可回退到默认语言对应消息并记录 key/locale。两边均缺失时显示安全通用提示，不把 key 或 `undefined` 暴露给用户；运行时回退不能作为英文验收通过。
- 插值和用户内容保持转义；含样式的翻译使用受控结构，不通过任意 HTML、脚本或执行表达式实现翻译。

## Server / Client、缓存与 Metadata

- 服务端按请求解析 locale 并加载所需消息；Client Component 接收相同初始 locale 和必要消息。避免在模块全局保存可变“当前语言”，防止用户之间串语言；不为翻译把整站改为 Client Components。
- 服务端与客户端使用同一 locale、时区、币种与显式 `Intl` 格式选项，确保首屏与 hydration 一致（避免 Node.js 服务端与浏览器默认格式选项差异引起水合不一致）；不能等挂载后才纠正整页语言，不能用关闭 hydration 检查掩盖不一致。根 `<html lang>`、页面标题、描述与可访问性文本跟随有效 locale。
- 翻译后的 HTML、Metadata、接口展示消息或报告缓存须按适用 locale 隔离；若未采用区分 locale 的 URL 路径而依赖 Cookie 或 `Accept-Language` 解析，HTTP/SSR 共享缓存必须配合 `Vary` 或禁用跨用户公共缓存，防止英文与中文响应串缓存。原始数据缓存保留业务 scope（详见 [数据访问与缓存工程约束](data-access.md)），并在展示边界本地化；沿用品牌/用户隔离，不把一次英文响应缓存给中文请求。
- 仅向客户端发送当前页面需要的消息，避免每次加载全部语言和领域字典。若采用公开的语言 URL，为确有对应页面的语言维护正确链接、canonical 与语言关联，不能生成不存在的英文路由。

## 格式、编码与布局兼容

- 日期、时间、数字、百分比、金额等通过统一格式化入口，显式传入 locale、真实币种、所需时区与一致的 `Intl` 选项，可复用原生 `Intl`。底层使用时间、数值及稳定枚举计算，不解析本地化字符串做排序、金额或指标运算；ISO/JSON 交换合同保持原语义。
- 中英文与混合文本保持 Unicode 原文，输入校验、数据库存取、URL 编码和导出须验证往返一致。表单、搜索与标签输入须兼容中文输入法（IME）组合状态（`isComposing` 期间回车确认候选词不得误触发表单提交）；字数上下限校验（如 2–80、5–300、5–500 字）使用统一边界，截断与摘要不拆断多字节字符或代理对。品牌归一、大小写比较及搜索语义按业务合同处理，不按界面语言改写名称或仅假定中文字符。
- 导出与下载（Markdown、HTML、JSON、CSV、Manifest）统一采用 UTF-8 编码，下载响应头兼容非 ASCII 品牌与文件命名（如 RFC 5987 `filename*`），且不改变不可变报告或交付包的指纹字节。
- 使用可伸缩、可换行的布局：Flex/Grid 容器子项配合 `min-w-0` 与合理的断词/换行规则，数据指标卡片与表格数字使用等宽数字（`tabular-nums`）；按钮、导航、表单和卡片不能按中文短标签写死尺寸。检查长英文、无空格长词、中文长名称、长 URL、表格及 Recharts 图表图例/坐标轴标签与 tooltip，必要截断时提供可访问的完整信息。
- 两种语言都在 375 / 768 / 1440 宽度和键盘操作下验收；弹窗、错误说明、焦点、状态与筛选不得因文本长度或语言切换丢失。

## 验证与维护

实施时执行 [双语言兼容矩阵](../08-验收场景与样例.md#i18n-checks)，分别记录两种 locale 的正常、边界与失败结果。基础 lint/typecheck/build 和文档检查不能证明语言切换、英文完整度、SSR 或布局行为已经通过。

当前无消息字典或 i18n 专项命令；未来接入时补齐 key/参数一致性检查和适用的集成验证，不编造当前脚本。字典、locale 解析、路由、格式化、错误映射、缓存或导出变化时，更新本规范、项目事实与相应验证；公共行为变更先更新 `ui-i18n-v1` 合同及产品追溯。独立文本修改也须同步核对两种语言。
