# 品牌删除设计

## Context

B04 品牌归档保持资料可读。B05 每次下载从源记录重建并校验指纹。B10 已建立独立额度和费用账本。D4 提供冻结、恢复及提前处理约定，现有真实资料入口关闭。

## Goals / Non-Goals

交付 B06 的双语影响预览、访问冻结与限期恢复。B07 负责物理清除、附件与备份流程。B17 负责邮箱验证交付。

## Decisions

- 在品牌行保存冻结时间和当前恢复期限。沿用 active/archived 描述资料状态。SQLite3/PostgreSQL 追加可空 UTC ISO 文本列，将活跃品牌唯一索引限定未冻结行，新增本人冻结名单索引。原表外键和旧数据兼容。各表按品牌索引整批读取范围计数。
- 冻结、限期调整及恢复在品牌归属锁下更新行与修订，复用品牌操作幂等记录。PostgreSQL 锁账户并更新品牌行，额度尝试锁同一品牌行。SQLite3 以立即事务串行写入。生成下载与冻结复用账户锁，下载指纹变化后旧地址持续拒绝。
- 服务端确认 Better Auth 权威会话。恢复使用邮箱已验证且冻结后 5 分钟内新建的登录会话。恢复到原 active 状态前检查一品牌名额。提前请求由受控 CLI 接收已人工核验的请求标识和截止时间，只能缩短现有期限。
- 复用现有品牌入口和表单变更模式，普通直链对冻结资源返回 404。独立恢复页只显示控制标识及时间。私有响应使用 no-store，品牌入口避免预取正文。无应用级缓存。
- 双方言使用 drizzle-kit 生成迁移并审核 SQL，重建 DDL 并比较空库与迁移结果。复用真实会话、双库 fixture 和 Chrome。

## Risks / Trade-offs

现阶段界面只能披露尚未接入的附件、报告和外部执行能力。真实恢复需要 B17 及实际运营渠道。窗口到期后状态保持冻结以供 B07 清除。
