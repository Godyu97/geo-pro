# Design

## Context

S-M0-01 和 AC-M0-01-1/2/3 规定最小品牌引导。账号与工作台复用已交付的 B01、B02 会话和语言。B04 交付品牌归档，D4 的删除冻结、身份恢复和清除由 B06–07 承接。

## Goals / Non-Goals

- 交付真实持久化、所有权、不可变实体版本、可继续草稿以及双语言的品牌页面。
- 用隔离环境验证上述行为与真实资料停收边界。题目仅作为草稿，监测、导出、删除与正式试点开放属于后续交付。

## Decisions

1. 工作台进入 `/dashboard/brands`。有活跃品牌时打开资料，没有时开始或继续 `/dashboard/brands/new`。品牌详情使用稳定 ID，历史可按版本查看，编辑复用三步表单。每次点击下一步或显式保存都会保存草稿。退出或超时只恢复已保存内容，浏览器不存草稿。语言切换复用 Cookie，业务地区使用地区代码（默认 CN），语言使用 BCP 47 标签（默认 zh-CN）。官网仅验证公开 HTTP(S) 地址格式，不访问目标或推断归属。
2. `brand` 记录所有者、当前状态、修订和实体版本指针。活跃状态的部分唯一索引按负责人约束，按所有者、状态、创建时间和 ID 分页读取归档。`brand_version` 保存不可变资料快照（含初步问题），以品牌 ID 和顺序版本为键。其余内容不拆成没有独立生命周期的表。
3. `brand_draft` 以负责人和目标为键，保存步骤、部分输入、草稿版本及关联的档案修订。`brand_operation` 以负责人和操作 UUID 去重，只保留输入的摘要和最小结果索引。正确重发返回已提交的结果，冲突不覆写。创建或更新同一事务内提交快照并消耗草稿。归档和恢复推进档案修订，旧表单须核对。表和索引由双方言 Drizzle Schema 生成，业务时间以 UTC ISO 字符串保存。
4. 复用 QueryConnection 的绑定参数及事务。PostgreSQL 事务锁定当前负责人行，SQLite3 使用现有 BEGIN IMMEDIATE 及外键开关。约束防止超限，归属查询和条件写入始终包含会话用户 ID。读列表用有界查询和快照连接，命令按依赖执行固定次数 SQL。两种迁移、已有账号升级、全量 DDL 导入和查询计划均在隔离库核对。
5. 私有页面使用 requireSession，JSON 接口检验当前会话、同源写入、Zod 严格输入、草稿和档案预期版本。响应禁止共享缓存。无新增依赖、业务缓存或发信。
6. 正式收集入口关闭。品牌操作限显式配置的回环验收环境。运行时使用独立测试库并明示只输入合成资料。测试资料由隔离库清理。真实资料请求受理及备份清除经过运行环境演练验证后才开放。

## Risks / Trade-offs

- 最后一次成功保存是恢复边界。故障或冲突期间表单保持输入，失败不假称已保留。后续清除任务需要覆盖业务版本、草稿和操作索引。
- 本地验证品牌历史的固定版本读取。真实报告和下载的跨模块验证随对应任务完成。
