# Design

## Context

品牌归属与单活跃品牌来自 B04，受控权限和事务审计来自 B08。B10 为 T-M0-05 的额度基础，D1/D2 定义逻辑计数、独立费用和试点政策。

## Decisions

1. 使用同源维护 JSON 接口作为首期输入渠道。服务端从 Better Auth 取得身份，复用 `runMaintenanceAction` 在同一事务中核验权限、写入不可变版本、写审计。维护请求包含不透明品牌 ID、预期版本、幂等键、固定原因及实际授权值。授权历史本身作为事件，当前值读取最高版本。
2. 每一品牌、额度类别与逻辑单元有一条记录。金额使用同币种的整数最小货币单位。单位预算包含所有供应商尝试，已知费用及未决尝试上界计入已承诺金额。重新授予不重置既有预留和结算数据。已有活动时固定同类预算币种。
3. 品牌行锁串行化同品牌的授权与额度写入，SQLite 使用现有立即事务。通过复合主键限定版本、逻辑单元和尝试读取，使用操作键唯一约束。用户端用单条查询读取本人当前活跃品牌、两类最新授权及批量聚合；不引入缓存。
4. 预留、尝试开始、成本核对和逻辑结算是独立操作。核对不要求品牌仍活跃或授权仍有效。释放须已无未核对尝试，并由调用方确认没有可采用的迟到结果。提供服务端合同，B11/B12 和内容生成接入后才执行真实动作。

## Migration Plan

双方言独立生成和审查迁移，更新全量 DDL，在隔离环境验证已有数据升级、DDL 导入、并发及审计失败回滚。
