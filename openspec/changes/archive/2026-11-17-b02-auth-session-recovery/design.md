# Design

## Context

动机和范围见 proposal.md。B01 已实现白名单返回地址、双语言表单及 Chrome E2E。当前 `requireSession` 直接读取会话，登录页未检查已有身份；认证 API 已捕获异常并返回安全 503。OpenSpec 配置中的“无 Playwright/仅中文”描述已落后于 B01，实施以真实 package.json、代码和现行双语言规范为准。

## Goals / Non-Goals

**Goals:** 统一服务端会话状态；保持薄路由；提供真实失效和故障反馈，复用既有验证工具。

**Non-Goals:** 不新增认证体系、Schema、DAO/cache 适配、业务草稿存储、品牌状态、邮件或费用动作。

## Decisions

1. `src/lib/auth/session.ts` 保留 server-only，集中解析 authenticated / anonymous / not-configured / unavailable，并在 React 请求内复用，避免页面和布局重复查询。不做跨请求缓存；认证仍由 Better Auth/PostgreSQL 决定，Cookie 存在性不授权。页面仅组合结果和展示。
2. 复用 `safeReturnTo`，集中构造带稳定 reason 的登录地址。登录页由服务器验证会话后跳转；错误查询值不决定权限。仅允许当前真实 `/dashboard`，保留安全查询和片段，未来业务路由随交付加入。
3. 用小型 Client Component 订阅 Better Auth 会话，在聚焦和每 60 秒检测失效；临时网络/503 展示可重试提示，不误称注销。确认失效或切换账号后整页导航，避免残留私有 RSC 缓存。客户端检查只改善体验，服务端鉴权仍不可省略。
4. 认证成功及退出成功采用整页替换，清理当前内存中的密码/私有界面；失败保持原表单或工作台。主动退出关闭该请求的 SDK session signal，避免失效监听与显式退出地址争抢导航；其他标签通过聚焦或周期检查发现撤销。当前不写 localStorage/sessionStorage/草稿；不为尚不存在的业务表单建设通用恢复框架，B04 接入非敏感草稿。
5. 使用现有集中消息与可访问状态/按钮；登录故障提供显式刷新重试。复用 Chrome 和 Node 原生测试，不新增依赖。故障探针仅存在隔离构建副本，不进入正式应用。
6. 保留当前 Better Auth 表与索引，无迁移/DDL 变化；SQL 仅在本地验证脚本按临时账号精确更新到期时间及清理。SQLite/Redis/业务资源归属不在本项已实现能力内，不据此声称双后端或跨品牌验收通过。

## Risks / Trade-offs

- [周期检查不是即时推送] → 聚焦/跨标签会话事件补充检查；每次敏感读写仍须服务端鉴权。
- [整页导航清除认证内存输入] → 只在身份变更/失效/成功时导航；非敏感业务草稿由 B04 提供独立恢复。
- [服务暂不可用] → 不当作无效密码或成功退出；显示本地化提示和显式重试，不重放写入。
- [品牌和收费流程未实现] → 当前只恢复工作台 GET，不提供虚构引导和自动收费动作；后续真实业务接口需补充权限及草稿联调。

## Migration Plan

无需数据迁移；通过现有构建交付。回退本次源码即可恢复此前认证界面，不改用户数据和会话格式。本轮只提交并推送，不部署。
