# monitoring-runs

## Purpose

让品牌负责人在采样开始前确认冻结题集、轨道和预算，并登记可刷新恢复的排队运行与额度预留。

## ADDED Requirements

### Requirement: 隔离执行与可恢复进度

系统 SHALL 对已登记运行执行可替换传输，并保存每次 Attempt、至多一条采用结果和费用状态。刷新或重启后 MUST 恢复进度。暂停和取消 MUST 停止尚未受理的单元并保留已受理结果与费用。取消 MUST NOT 减少计划槽位分母。官方 API 未接通时 MUST 拒绝执行，公共界面 MUST NOT 生成模拟成功。

#### Scenario: 三成功一待核对

- **GIVEN** 运行有 4 个槽位且隔离传输对其中 1 个返回未知费用
- **WHEN** 执行完成
- **THEN** 计划分母仍为 4，3 个槽位采用结果，1 个进入待核对，系统不立即重发该槽位

#### Scenario: 额度只够一个新单元

- **GIVEN** 剩余次数或预算只允许一个新的付费单元
- **WHEN** 两个执行同时开始
- **THEN** 只有一个单元执行，另一个暂停

### Requirement: 重试、晚到与分析重做

安全失败的槽位 MUST 最多额外重试两次。未知受理或未知费用 MUST 进入待核对并保留上界，不得盲目重发。晚到原文和费用 MUST 保留并标记。分析重做 MUST 复用已采用原文且不得增加采样费用。结算和释放 MUST 幂等。

#### Scenario: 分析重做

- **GIVEN** 槽位已采用一条已知费用的原文
- **WHEN** 负责人要求重做分析
- **THEN** 新 Attempt 复用该原文，已知采样费用不变

### Requirement: 本人用量与费用核对

系统 MUST 只向本人展示其供应商预计、实际、预留和待核对金额。未知金额 MUST NOT 显示为 0。试点客户应付 MUST 为 0。不同币种 MUST 分开汇总。列表 MUST 有界分页，并批量关联运行与尝试。未授权访问 MUST 看不到内容。界面语言切换 MUST NOT 改变金额。

#### Scenario: 本人明细

- **GIVEN** 负责人有预留、实际和待核对费用，另一位负责人也有记录
- **WHEN** 负责人打开用量明细
- **THEN** 只看到本人记录，未知费用保持待核对，并可以回到对应运行
