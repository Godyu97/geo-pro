# 执行与恢复设计

## Context

登记事务已经创建 queued 运行、槽位和预留。执行必须在新的付费单元开始前重新检查授权和额度，并且不能把官方端口未接通时的结果写成真实采样。

## Goals / Non-Goals

**Goals:**

- 保存每次采样或分析重做的 Attempt，每个槽位最多采用一条结果。
- 安全失败最多再试两次；未知结果进入待核对并保留上界。
- 暂停、继续、取消保留已受理结果和费用。取消不减少计划分母。
- 本人用量按时间和标识分页，关联尝试一次批量读取。

**Non-Goals:**

- 选择真实供应商、核验真实价格或接受真实采样结果。
- 从公共界面输入原始回答或生成模拟成功。

## Decisions

1. 测试注入明确标注的隔离传输；官方端口在写入前拒绝。
2. 执行使用监测事务和品牌行锁直接写额度，不在事务内再开启额度事务。
3. 新单元同时受次数和预算上界约束。已开始预留的安全重试不计入新单元。
4. 晚到原文只由服务端测试入口记录；公开接口只接受暂停、继续、取消、分析重做和数字费用核对。
5. 用量列表固定每页 20 条，游标为创建时间加标识。未知金额保持未知，客户应付固定为 0。

## Risks / Trade-offs

- 小样本下 PostgreSQL 可能选择顺序扫描。索引存在，关闭顺序扫描后计划命中品牌近期预留索引。
- 隔离验收使用合成数据和调用方确认的上界，不能代表真实供应商费用。

## Migration Plan

双方言增加 Attempt 表，并允许运行与槽位进入执行期状态。SQLite 以重建表保持最终列顺序。回滚需先停止执行写入，再按迁移逆序处理；已产生的 Attempt 不能静默删除。

## Open Questions

无。真实通道的价格和结果合同由后续供应商任务定义。
