# Design

## Context

动机见 proposal.md。当前官网为单个较大的 Server Component，已有字典、模块卡和语言选择；B02 提供四态 getSessionState，认证页和工作台已有安全分流。现有 Playwright 生产副本支持账号未配置/故障注入，测试环境使用本地 PostgreSQL。

## Goals / Non-Goals

**Goals:** 让官网说明与实际能力一致，在首屏服务端完成身份入口选择，复用现有设计系统与双语言运行时。

**Non-Goals:** 不增加业务状态存储、能力台账、通用功能开关、认证策略或新路由；不预先接入品牌数据库与邮件服务。

## Decisions

1. 将官网组合移至 `src/features/marketing/home-page.tsx`，路由只导出页面。继续默认 Server Component，按请求调用现有 `getSessionState`，只使用状态、不输出会话。客户端 Cookie 猜测会误认身份，故沿用服务端权威。
2. 匿名首屏保留“开始体验”至 `/login?mode=signup` 和登录入口；有效身份显示“继续使用”至 `/dashboard`。现阶段工作台是唯一真实业务接续点；B04 交付后由该入口的工作台分流接入引导，避免新增指向不存在页面的链接。
3. 添加“当前可以做什么”区域，展示账号与工作台、品牌建档、真实监测三个公开状态及 D5 试点限制；无真实通道版本时只说明未开放，不构建空台账或公开内部字段。未配置/故障以现有会话状态显示安全提示，保持产品说明可读并链接到可恢复账号页。
4. 两种语言集中维护完整句子，保留已验收的跳转主文案及 Metadata。沿用现有色板、可换行导航、锚点和焦点样式，流程显式标为示意。
5. 在 B03 交付记录建立消息到来源的映射、仓库维护者承担的文案维护责任及 B04/B09/B16/B17 等更新触发条件，不引入 CMS 或额外发布管线。
6. 扩充现有 E2E：两种语言与三种宽度，匿名/有效/无效身份，未配置/故障、SSR、不跨身份缓存、语言/片段保留和键盘。复用故障副本，不在正式应用添加测试开关；运行已有认证专项回归。

## Risks / Trade-offs

- [公开页面额外会话读取] → 使用已有请求内复用和受控故障状态；沿用 no-store，防止身份/语言串缓存。
- [说明随交付过期] → 明确维护责任、来源与更新触发；真实开放必须随相应 Issue 验收调整中英文及测试。
- [B04 尚未交付] → 当前仅核验官网→真实工作台；不宣称引导端到端通过，B04 合并时完成后续联调。
- [没有真实邮件/通道] → 明示真实试点未开放，不能把技术账号体验解释成真实业务开放。

## Migration Plan

无需迁移、DDL、依赖或环境变量改动。使用当前分支提交并推送，不部署；回退本次代码即可恢复原官网，不触及用户数据。
