# Proposal

## Why

负责人需要在采样开始前确认题集、轨道和预算，并得到可刷新恢复的排队运行。Issue #11 对应 R-M0-05、S-M0-05 的受理部分，以及 AC-M0-05-1。前置 #23、#9、#17、#10 已关闭。

## What Changes

- 按冻结题集、通道版本和采样协议预览题数 × 通道数 × 重复数，并分开确认官方 API 与消费者人工轨道。
- 正式登记持久的 queued Run/Slot。API 轨道按逻辑槽位预留额度；消费者轨道不产生平台付费。
- 同一操作和同一输入返回原运行与原预留；改输入、过期预览、无可信上界、额度不足或未验证邮箱时拒绝并给出下一步。

## Capabilities

### New Capabilities

- `monitoring-runs`：登记可恢复的排队监测运行和预算预留。

### Modified Capabilities

## Impact

新增监测运行表、服务端接口和双语确认/详情页。复用题集版本、通道资格、邮箱验证和试点额度账本。不新增依赖、缓存或供应商调用。

## Out-of-Scope

供应商执行、Attempt、费用结算、暂停/继续/取消、AC-M0-05-2、AC-M0-05-3，以及真实渠道开通（#31）。不得把 queued 当成监测成功。
