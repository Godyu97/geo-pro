# Design

## Context

运行确认页目前只检查通道资格并返回 `RUN_NOT_OPEN`。额度账本已能按逻辑槽位预留，题集已能冻结版本和主指标标记。本变更只把确认变成排队登记，不启动采样。

## Goals / Non-Goals

**Goals:**

- 预览只读，正式登记在一个事务内写入 Run、Slot 和 API 预留。
- 用操作编号和签名预览实现幂等、冲突和 15 分钟过期。
- 官方 API 与消费者人工分开保存。客户应付固定为 0，未知供应商下界保持未知。

**Non-Goals:**

- 不创建 Attempt，不调用外部供应商，不结算或释放预留。
- 不改变旧的 `{ space, channelIds }` 资格检查。

## Decisions

1. 新表 `monitoring_run` 与 `monitoring_slot` 只保存 `queued`。运行级联品牌，槽位级联运行；预留 ID 不设外键，避免和额度清除形成交叉级联。
2. 逻辑槽位 = 已确认题 × 本轨通道 × 重复次数（1–3）。`primary` 题计入自然发现，比较或品牌题仍在范围内但不进主指标。
3. API 轨道要求已验证邮箱、未过期 verified 通道、有效采样额度和显式可信上界。每槽一条 `sampling` 预留，上界为确认的单槽金额。消费者轨道不写预留，供应商金额保持 null。
4. 预览用服务端密钥对范围签名。受理时重读题集、通道和额度版本；签名不符、超过 15 分钟或版本变化分别拒绝。相同操作编号和相同指纹返回原记录。
5. 品牌行锁串行化同一品牌的并发登记。列表和槽位各用一条按品牌或运行 ID 的查询，避免逐槽读取。
6. 详情页和确认页的最近运行提供刷新恢复。界面语言只改变文案，金额、币种和题集版本来自已保存记录。

## Risks / Trade-offs

- 预留在 #12 执行前会占用额度。取消和释放不在本次范围，负责人需等待后续恢复能力。
- 隔离验收使用调用方确认的上界，不代表真实供应商价格。

## Migration Plan

新增双方言迁移和全量 DDL。旧资格接口保持可用。没有数据回填。

## Open Questions

无。真实价格与正式执行留在 #12 和 #31。
