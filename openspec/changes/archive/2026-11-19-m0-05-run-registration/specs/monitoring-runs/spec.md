# monitoring-runs

## Purpose

让品牌负责人在采样开始前确认冻结题集、轨道和预算，并登记可刷新恢复的排队运行与额度预留。

## ADDED Requirements

### Requirement: 范围预览与分轨确认

系统 SHALL 让负责人基于本人的冻结题集、通道版本和采样协议预览题数、通道数与 1–3 次重复。官方 API 与消费者人工 MUST 分别确认和保存。已确认题全部进入范围，只有合格非品牌题进入自然发现。未登录、其他品牌和冻结品牌的读写 MUST 被拒绝。

#### Scenario: 四题中三题进入自然发现

- **GIVEN** 冻结题集有 3 个合格非品牌题和 1 个品牌比较题
- **WHEN** 负责人分别预览并登记两个轨道
- **THEN** 每个运行保存 4 题范围和 3 题自然发现，两个轨道不能合成一个运行

#### Scenario: 重复次数越界

- **WHEN** 请求的重复次数小于 1 或大于 3
- **THEN** 系统拒绝登记且不创建运行或预留

### Requirement: 幂等登记与预算硬顶

系统 MUST 以同一操作和同一输入只保留一个 queued 运行、一组槽位和同一组 API 预留。改输入 MUST 冲突。预览超过 15 分钟、通道或额度版本变化、没有可信上界、额度或预算不足时 MUST 拒绝，并给出可执行下一步。未知金额不得写成 0。试点客户应付为 0。

#### Scenario: 连续确认三次

- **WHEN** 同一确认被连续或并发提交 3 次
- **THEN** 只存在一个运行和一组槽位，额度预留不重复

#### Scenario: 付费路径门禁

- **WHEN** 未验证邮箱、其他品牌或缺少可信上界的请求登记官方 API
- **THEN** 系统拒绝受理且不预留额度；消费者人工路径不产生平台付费

### Requirement: 刷新后恢复排队范围

系统 SHALL 让负责人在刷新后看到原 queued 范围、题集版本、金额和预留。界面语言切换不得改变金额、币种或冻结题集。queued MUST NOT 表示采样已完成。

#### Scenario: 刷新详情

- **GIVEN** 运行已经登记
- **WHEN** 负责人刷新详情或回到确认页
- **THEN** 范围、预留和金额与登记时一致，并标明采样尚未开始
