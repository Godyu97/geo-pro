# Design

## Context

B15 已有本人设置页。B04 DAO 负责活跃档案、归档、实体版本和草稿，品牌资料仅在显式回环验收模式中可读写。B08 的维护授权与资源归属独立。

## Goals / Non-Goals

用现有页面、会话、双库和 UI 组件交付同步生成及受保护下载。本轮负责本人当前数据，未来正式交付包和报告分别遵循自身规格。

## Decisions

1. 设置页服务端核验会话并加载该账号最近一次生成状态。客户端保留所选范围，显式触发生成和下载。生成接口验证同源、当前页面身份、范围、语言和前一记录 ID。下载接口独立核验当前会话与记录归属。授权和格式均在服务端校验。
2. `user_data_export` 按 `owner_id` 主键保留一条记录。范围以两项位值记录，请求与已生成范围共同表达成功、部分成功、失败。记录含随机下载 ID、语言、时间和完整性指纹。账号删除级联移除记录。文件内容从已获授权的当前数据生成，存储仅限生成元数据。下载复算指纹，源变化或开放条件变化时拒绝旧地址。
3. 导出与品牌写入共享负责人事务边界。PostgreSQL 锁账号行，SQLite 使用现有立即事务。相同前一记录 ID 的请求只生成一次。每个范围独立读取，失败回滚至保存点，保留其他完整范围。最小显式投影仅读取 `user.name`、`user.email` 和品牌内容字段。
4. 历史版本和草稿用有界批次读取，复用品牌归属索引、版本联合主键和草稿联合主键。草稿仅包含本人新建草稿及归属仍有效的品牌范围。品牌读取有固定的字节上限。超过上限时该范围整体标记失败。
5. 文件为版本化 UTF-8 JSON。附件使用固定、按生成语言选择的文件名及 `filename*`，内容记录生成语言、请求及实际范围。响应使用 `private, no-store`。

## Risks / Trade-offs

- 记录仅指向最近一次生成的数据版本。资料改变或再次生成后，用户可按当前资料生成新文件。
- 较大品牌集合可能超出同步导出上限。界面明确标出失败范围，个人资料仍可单独导出。
- B06 新增冻结状态时需要让冻结数据退出所有普通读取入口，包括导出；B07 核对清除路径和备份边界。

## Migration Plan

用 `pnpm db:generate` 生成双方言增量迁移，审核 SQL，运行 `pnpm db:ddl` 与 `pnpm db:ddl:check`。在隔离库验证由 B04 升级、重复迁移和全量 DDL。先迁移再应用代码。
