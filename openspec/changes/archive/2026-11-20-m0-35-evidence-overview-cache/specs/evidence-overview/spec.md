# evidence-overview Delta

## ADDED Requirements

### Requirement: 概览批量读取与读缓存

系统 SHALL 在确认当前用户拥有目标品牌且品牌未冻结之后才读取概览缓存。概览 MUST 用集合查询装载采纳尝试和题型，SQL 次数不得随样本数线性增长。缓存键 MUST 包含负责人、品牌、统计 scope、规则版本和实体/分析/任务新鲜度，且 MUST NOT 按界面语言分键。Redis 不可用时 MUST 回源数据库，MUST NOT 改用 memory 冒充共享缓存。证据入证、分析修订、品牌更新、冻结、清除或优化任务在提交成功后，后续读取 MUST 反映新结果或拒绝访问。指标口径保持不变。

#### Scenario: 大批量样本的查询次数

- **GIVEN** 同一 scope 下分别有 30 条和 120 条已入证样本
- **WHEN** 读取两次概览
- **THEN** 120 条样本的 SQL 次数不随样本数线性增加，且第二次命中缓存时不再重复装载样本

#### Scenario: Redis 不可用时回源

- **GIVEN** 默认 Redis 缓存不可连接
- **WHEN** 品牌负责人读取概览
- **THEN** 返回数据库中的当前聚合，并记录缓存不可用，不改用 memory 冒充共享缓存

#### Scenario: 修订、任务变更和冻结

- **GIVEN** 概览已被缓存
- **WHEN** 分析修订、优化任务状态变更或品牌被冻结、清除并提交成功
- **THEN** 再次读取反映新的推荐结果或任务状态，冻结和清除后的读取被拒绝且不返回旧聚合
