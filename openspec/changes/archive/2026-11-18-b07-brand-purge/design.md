# 品牌清除设计

## Context

B06 冻结与恢复以账号锁和品牌行锁串行化。B05 只持久化生成记录，实际下载时重建并核对指纹。B10 费用记录通过品牌外键级联。

## Goals / Non-Goals

清除当前已接入的客户正文与副本，独立保留最小费用凭证。让隔离恢复先重放删除决定，再允许应用读取。真实备份轮换与报告页面分别由 #21 和 #30 验收。

## Decisions

- 受控 CLI 以 `restore_until, id` 索引选取有界批次。每品牌先锁负责人再锁品牌，与恢复、导出及额度同序协调。PostgreSQL 使用行锁，SQLite3 使用即时事务。单品牌事务内按正文、导出、费用执行独立保存点，凭证记录成功步骤及失败或等待原因。未知结果以持久化凭证为准。
- 正文使用按键集合删除。旧品牌操作只留下去指纹的幂等标记。历史草稿操作缺少归属字段，清除时使同一账号的旧草稿请求键失效。新操作明确保存作用域。仅失效可能包含目标品牌的导出记录。
- 未决费用继续由原账本按既有授权核对。所有尝试进入已知状态后，集合写入由不透明关联、金额、币种、状态和时间组成的费用记录，再清除品牌外键链。两个后端维护各自迁移和全量 DDL。
- 从恢复点之外保存按页读取的清除记录。离线按品牌重放，核对归属并冻结可能回滚为活跃的品牌，随后执行相同清除步骤。报告消费者在鉴权后查询清除记录并附加证据状态，原快照字节独立传递。

## Risks / Trade-offs

已下载文件在系统权限边界之外。未来存储接入须按品牌限域，隔离旧链接，并补可重试清除、快照一致性和离线恢复回归。备份内历史费用可能过时，恢复时需要独立的账务校对。
