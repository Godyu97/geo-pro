# evidence-overview Specification

## Purpose
在同一冻结过滤条件下为品牌负责人提供可解释的提及/推荐/官网引用概览，并下钻到同口径回答原文，使空数据、小样本与未知比例可见且不被伪造分数掩盖。

## Requirements

### Requirement: 同口径题等权主卡与池化明细

系统 SHALL 按品牌、时间窗、单一轨道（API 或消费者）、联网模式与地区等同一 scope 聚合有效样本。主卡 MUST 仅纳入 discovery/scenario/constraint 非品牌题，使用题等权算术平均，并同时展示逐题分子分母与单独标明的样本池化比率。系统 MUST NOT 跨轨道或不同联网条件平均，MUST NOT 输出综合 GEO 分或伪造整数分母。

#### Scenario: 两题推荐金样

- **GIVEN** 题 1 推荐 1/2、题 2 推荐 3/3 共 5 条可判断样本
- **WHEN** 打开概览
- **THEN** 主卡题等权推荐率为 75%，池化明细为 4/5=80% 且单独标明，并可定位全部 5 条样本

#### Scenario: 无有效样本

- **GIVEN** 当前 scope 无有效样本
- **WHEN** 打开概览
- **THEN** 指标显示 N/A 与可执行下一步（补采/入证），不出现伪造分数或增长

### Requirement: 轨道隔离与下钻一致

筛选、KPI、趋势占位与回答列表 MUST 使用同一 scope。切换消费者轨或时间窗 MUST 同步更新列表且 MUST NOT 混入另一轨道数据。未登录或非负责人直接请求详情 MUST 被拒绝且无内容泄露。

#### Scenario: 消费者轨不混入 API

- **GIVEN** 同品牌同时存在 model_api 与 consumer_ui 样本
- **WHEN** scope 选择 consumer_ui
- **THEN** KPI 与列表仅含消费者样本，数值与原文口径一致

### Requirement: 数据质量与任务入口空态

系统 SHALL 展示覆盖率、未知比例、小样本提示及官网引用不适用原因。首页最多 3 条优先建议/进行中任务入口；优化任务未生成时 MUST 给明确空态或已有证据下一步，MUST NOT 注入演示数字到真实工作台。

#### Scenario: 优化任务未交付

- **GIVEN** 已有部分有效证据但尚无优化任务
- **WHEN** 查看概览任务区
- **THEN** 显示空态与查看原文/补采动作，不捏造建议文案冒充诊断结果

### Requirement: 概览批量读取与读缓存

系统 SHALL 在确认当前用户拥有目标品牌且品牌未冻结之后才读取概览缓存。概览 MUST 用集合查询装载采纳尝试和题型，SQL 次数不得随样本数线性增长。缓存键 MUST 包含负责人、品牌、统计 scope、规则版本和实体/分析/任务新鲜度，且 MUST NOT 按界面语言分键。Redis 不可用时 MUST 回源数据库，MUST NOT 改用 memory 冒充共享缓存。证据入证、分析修订、品牌更新、冻结、清除或优化任务在提交成功后，后续读取 MUST 反映新结果或拒绝访问。指标口径保持不变。

#### Scenario: 大批量样本的查询次数

- **GIVEN** 同一 scope 下分别有 30 条和 120 条已入证样本
- **WHEN** 读取两次概览
- **THEN** 120 条样本的 SQL 次数不随样本数线性增加，且第二次命中缓存时不再重复装载样本

#### Scenario: Redis 不可用时回源

- **GIVEN** 默认 Redis 缓存不可连接
- **WHEN** 品牌负责人读取概览
- **THEN** 返回数据库中的当前聚合，并记录缓存不可用，不改用 memory 冒充共享缓存

#### Scenario: 修订、任务变更和冻结

- **GIVEN** 概览已被缓存
- **WHEN** 分析修订、优化任务状态变更或品牌被冻结、清除并提交成功
- **THEN** 再次读取反映新的推荐结果或任务状态，冻结和清除后的读取被拒绝且不返回旧聚合
